# 全国配套项目 · 完成核销情况一览表

各区域战役项目**完成与核销进度**可视化看板。发布在 GitHub Pages，每周更新，供领导查看。

数据来源：腾讯文档「全国配套项目执行追踪群-H2」表格。

---

## 功能

- **顶部 5 个 KPI**：规划场次 / 已开展 / 已核销 / 待核销场次 / 覆盖人数
- **三层筛选**：区域（8 个）→ 肺肿线（早肺 / 晚肺）→ 战役（**级联，只显示匹配的战役**）
- **三种视图**：
  - `按区域` — 各区域横向条形图（已核销 / 已开展未核销 / 未开展 三段堆叠）
  - `按战役` — 各战役横向条形图
  - `明细表` — 区域 × 战役 交叉表
- **点击弹层**：
  - 点区域 → 该区域下**各战役明细**卡片
  - 点战役 → 该战役下**各区域明细**卡片
  - 卡片内含规划 / 已开展 / 已核销 / 取消 / 覆盖人数 及原表备注

## 更新数据（三步）

```bash
cd settlement_dashboard

# 1. 从腾讯文档拉取各战役 sheet
python export_sheets.py

# 2. 解析生成 data.json
python build_data.py

# 3. 注入模板生成 index.html
python build_index.py
```

然后在本机手动 `git add / commit / push`，GitHub Pages 自动发布。

## 文件说明

| 文件 | 说明 |
|------|------|
| `export_sheets.py` | 调腾讯文档 MCP 导出 11 张 sheet → `raw/*.csv` |
| `build_data.py` | 解析 `raw/*.csv` → `data.json`（含区域归一、子战役拆分、缺失合计行补齐） |
| `build_index.py` | 把 `data.json` 注入 `template.html` → `index.html` |
| `template.html` | 页面模板（设计 + 逻辑），含 `/*__DATA__*/` 占位符 |
| `index.html` | **最终发布产物**，单文件零依赖 |
| `data.json` | 结构化数据（13 个战役 × 8 个区域） |

## 关键口径

### 区域映射（重要）

各战役 sheet 里的区域名与「项目总览」sheet 不完全一致：

| 战役 sheet | 项目总览 | 说明 |
|-----------|---------|------|
| 东部区域 | 东部区域 | 同名 |
| 南部区域 | 南部区域 | 同名 |
| 东南区域 | 东南区域 | 同名 |
| **西部区域** | **中部区域** | 同一区域的不同叫法 |
| 北部区域 | 北部区域 | 同名 |
| 西北区域 | 西北区域 | 同名 |
| 华北区域 | 华北区域 | 同名 |
| 湘桂区域 | *(总览未分列)* | 独立区域 |

### 排序规则

**所有展示区（按区域 / 按战役 / 明细表 / 两个弹层明细）一律按「核销率」从高到低排序**，每次更新数据后自动生效，无需手工调整。

- 核销率 = 已核销 ÷ 已开展 × 100%
- 已开展为 0、核销率无法计算的项，统一置底（显示为 `—`）
- 同率时按「已核销场次」多者优先，再按名称兜底，保证每次刷新顺序稳定不跳动

### 指标定义

| 指标 | 定义 |
|------|------|
| 规划场次 | 分配场次 |
| 已开展场次 | 项目开始 - 统计日 已开展 |
| 已核销场次 | 已完成核销场次 |
| 核销率 | 已核销 ÷ 已开展 |
| 执行率 | 已开展 ÷ 规划 |
| 规划进度 | 确定场次（含已开）÷ 规划 |

### 数据源选择

**分配/完成数据以各项目明细 sheet 为准**，不使用「项目总览」sheet。
原因：总览表的区域分配列已删除（原分配数不准），各项目 sheet 是唯一权威来源。
